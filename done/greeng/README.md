# Настраиваем операционную систему для клавиатуры

- [ZMK](https://zmk.dev) — Zephyr Mechanical Keyboard — платформа для сборки клавиатурных прошивок на базе Zephyr

> [!WARNING]
> По умолчанию — разработческая версия.\
> Для выбора стабильной пошарьтесь по менюшкам.

- [Целый зоопарк](https://v0-3-branch.zmk.dev/docs/hardware) железок, на которых с помощью ZMK можно построить свою клавиатуру

- [Zephyr](https://zephyrproject.org) — операционная система реального времени (RTOS) для мелких железок

> [!NOTE]
> `AVR` тут не  ждут совсем.\
> Для этого есть другие отличные инструменты.

- **[TMK](https://github.com/tmk/tmk_keyboard/wiki)** — — довольно низкоуровневая, подходит для слабых микроконтроллеров и подключения клавиатур с древними интерфейсами
- **[QMK](https://qmk.fm)** — *Quantum Mechanical Keyboard* — растёт из **TMK**, мегапопулярна для контроллеров `AVR` *(читай — Arduino)*, хороша в основном для проводных клавиатур

> [!TIP]
> Операционка поверх операционки.\
> Все `•MK` — *как бы* операционки специально для клавиатур.
> Разруливают низкоуровневые проблемы.
> Нам остаётся только прикладной уровень.

> [!IMPORTANT]
> Что за низкоуровневые проблемы у клавиатур?\
> Дребезг • порог tap/hold • интервалы • исключения • электричество • …

- Кстати, хороший повод законтрибьютить в open source.


## Инсталляция и настройка

Сначала всё хорошо идёт [по инструкции](https://zmk.dev/docs/user-setup). Ну а потом — нюансы.

### Расскажем системе про нашу железку

`zmk keyboard new` — создаём новую клавиатуру

```bash

greeng.conf
greeng.keymap

```

Дальше настраиваем [по инструкции](https://zmk.dev/docs/hardware-integration/new-shield).

- `Kconfig.•` — имя, код, настройки по умолчанию
- `green.conf` — шаблон рекомендаций настроек
- `green.zmk.yml` — для публикации в каталоге оборудования
- `greeng-layouts.dtsi` — для визуальной раскладки в ZMK Studio


#### `green.overlay` — описание электронной части устройства

------------------------------

Давайте сами сначала вспомним, как устроена эта электронная часть.

> [!TIP]
> GPIO-шпаргалка\
> Nord • `D9`\
> East • `D7`\
> South • `D8`\
> West • `D10`\

- Кнопка замыкает свой пин на землю
- Соответственно, по умолчанию пин подтянут к питанию
------------------------------
- **kscan → compatible** — какие события будут считаться нажатием кнопки
	- у нас схема «одна кнопка — один GPIO-пин»
	- [значит](https://zmk.dev/docs/config/kscan#direct-gpio-driver), нужно так: `compatible = "zmk,kscan-gpio-direct"`
- **kscan → input_gpios** — каждая строка описывает одну кнопку
	- `&xiao_d 3` — так описываем кнопку на пине `D3`
	- `(GPIO_ACTIVE_LOW | GPIO_PULL_UP)` — так описываем логику срабатывания этой кнопки
- **kscan → wakeup_source** — нажатие на любую кнопку будит устройство

> [!WARNING]
> А что такое Devicetree?\
> Этот термин начинает мелькать, если внимательно читать документацию.\
> Переводится в лоб — *дерево устройств*.\
> Обслуживает это дерево [Zephyr](https://zephyrproject.org).\
> Да, очередной уровень абстракции.

- **default_transform** — нумерует сигналы из электрической части

### Можно делать Hello, world!

`zmk keyboard add` — добавляем эту новую клавиатуру в проект

> [!WARNING]
> …иии внезапно мы тут без toolchain.\
> Зато с GitHub Actions, прилетевших из шаблона проекта.

- Неприятно, конечно, зависеть от облака.
- Но на дворе 2026 год.

Посмотрим, что там в GitHub Actions:
```bash
gh run list
```

Мониторим конкретную сборку:
```bash
gh run watch <ID сборки>
```

Скачиваем артефакты конкретной завершённой сборки:
```bash
gh run download <ID сборки>
```

Переход в режим загрузки — дважды `Reset` на плате.
После этого увидим `/Volumes/XIAO-SENSE/`

Ну и заливка:
```bash
cp greeng-seeeduino_xiao_ble-zmk.uf2 /Volumes/XIAO-SENSE/
```


### Меняем наш конкретный набор клавиш

- Теперь уже в `config/greeng.keymap` проекта, а не клавиатуры.
- Вместо клавиш пишем выражения с [модификаторами](https://zmk.dev/docs/keymaps/modifiers) (можно вкладывать).
- [Таблица клавиатурных кодировок](https://zmk.dev/docs/keymaps/list-of-keycodes) очень пригодится.
